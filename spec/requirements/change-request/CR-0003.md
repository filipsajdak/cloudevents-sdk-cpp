# CR-0003: An event keeps the JSON document its decoder built, in a new `ce::v3` generation

## What prompted this

Reading a typed payload parses its JSON twice and serialises it once.
The decoder parses the document, `decode_data` dumps the `data` member back to `json_text`, and `data_as` parses that text again.
Sending a typed payload has the mirror cost: `set_data` dumps the payload to text, and the encoder parses it again to splice it into the document.
The v0.4.0 audit recorded this as P3.

Measured with `bench/codec_bench` (Homebrew Clang 23, Release, median CPU time) on a 150-byte event carrying a four-field payload:

| codec | `decode` + `data_as` today | one parse | the dump alone |
|---|---:|---:|---:|
| nlohmann | 3542 ns | 2618 ns | 334 ns |
| rapidjson | 1544 ns | 1201 ns | 238 ns |
| boost.json | 1535 ns | 1229 ns | 88 ns |
| glaze | 2299 ns | 1725 ns | 129 ns |

One parse saves 20 to 26 percent.
Removing the dump as well saves 88 to 334 ns more, and only a change to what an event holds can remove it.

## What is requested

**An event can hold a parsed JSON document.**
`data_t` gains a fifth alternative, `json_document`.
It owns a codec's DOM behind type erasure, so the core header still names no codec type.
It is immutable once built and shared between copies, so an event can be copied across threads without duplicating or racing on its payload.

**The JSON format keeps and reuses it.**
- The decoder stores the `data` member as a `json_document`, unless the document is longer than a retention limit.
  Above the limit it stores `json_text`, so a hostile document cannot pin its expanded DOM in memory for the life of the event.
  The limit is a decode option, 64 KiB by default; 0 always stores text.
- The encoder copies a `json_document` built by its own codec into the output, without serialising or parsing it.
- A document built by one codec and used with another is converted by serialising with the first and parsing with the second.
  The fast path is selected by a codec identity check, never by a cast.

**Two documents compare as JSON values.**
Built by the same codec, they are equal when the codec's `equal` says so.
Built by different codecs, they are equal when their compact serialisations are.

**The codec concept requires what this needs.**
The v3 `json_codec` requires `C::equal(const value&, const value&) -> bool` and a copy-constructible `value`.
The three in-tree codecs gain `equal`, which is an addition and keeps their v1 declarations.

**Typed payloads use one parse.**
- `decode_as<T, Codec>(text)` parses once and returns `decoded<T>`, an aggregate naming the event and the payload.
- `decode_batch_as<T, Codec>(text)` does the same for a batch.
- `from_value_as<T, Codec>(document)` does it for a document the caller has already parsed.
- `encode_as<T, Codec>(event, payload)` writes the payload's DOM straight into the output document.
- `set_data<T, Codec>` stores a `json_document`, and `data_as<T, Codec>` reads one built by `Codec` without parsing.

These live in `format/typed_payload.hpp`, beside `data_as` and `set_data`.

**The change is a new generation.**
`data_t` is a v0.4.0 declaration, so `SWR-BUILD-0006` and `docs/SPEC.md` section 3 rule 4 put the change in `ce::inline v3`.
`ce::v2` keeps what v0.4.0 published and takes only fixes that keep its declarations, as `ce::v1` does.
ADR-0010 applies the layout ADR-0009 set for v1 and v2.

## Requirements this changes

Each amendment lands with the implementation and its tests, so main never states behaviour its suites do not verify.

| requirement | today | after this request |
|---|---|---|
| `SWR-CORE-0012` | `data_t` has exactly four alternatives | five: `std::monostate`, `std::string`, `binary`, `json_text` and `json_document` |
| `SWR-CORE-0013` | JSON payloads are carried as text | a caller-supplied JSON payload is carried as text; the core header still names no codec type |
| `SWR-JSON-0015` | `json_text` is parsed and spliced under `data` | unchanged for `json_text`; `SWR-JSON-0041` covers `json_document` |
| `SWR-JSON-0019` | `data` decodes to `json_text` | `data` decodes to `json_document`, within the limit of `SWR-JSON-0040` |
| `SWR-EXT-0005` | typed payloads go through text | unchanged contract; `SWR-EXT-0011` and `SWR-EXT-0012` add the DOM paths |
| `SWR-BUILD-0005` | the inline namespace is `ce::v2`, sharing with `ce::v1` | the inline namespace is `ce::v3`, sharing with `ce::v2` and `ce::v1` |
| `SWR-BUILD-0006` | a breaking change goes to `ce::v2` | a breaking change goes to a new namespace; this request is its second use |

New requirements, in `reviewed` status until this request is approved:
`SWR-CORE-0031` to `SWR-CORE-0034`, `SWR-JSON-0039` to `SWR-JSON-0042`, `SWR-EXT-0007` to `SWR-EXT-0012` and `SWR-BUILD-0012`.

## What this costs

- **A third event model.** v2 joins v1 as a frozen generation, with its headers under `include/cloudevents/v2/` and its suites under `test/v2/`.
- **Every visitor of `data_t` sees a new alternative.** Code that visits all four exhaustively fails to compile against v3 until it handles `json_document`.
  That is the migration, and it is why this is a new generation.
- **Third-party codecs must add `equal`** to move to v3.
  They keep working with v1 and v2 unchanged.
- **A retained DOM costs more memory than its text.**
  The retention limit bounds it per event, but an event holding a `json_document` is larger than one holding the same payload as text.
- **Equality of documents from different codecs costs two serialisations.**

## Alternatives considered and declined

- **Add a one-parse `decode_as` and keep `json_text`.**
  Saves the second parse, not the dump, and changes no declaration.
  Declined by the owner on 2026-09-23 in favour of removing both.
- **Make `json_text` hold an optional DOM and produce its text lazily.**
  `raw` would stop being a public member, and producing text lazily under `const` needs synchronisation on every read.
- **Keep the typed value in typed events only.**
  Leaves every untyped decode and re-encode paying the dump.
- **Change `ce::v2` in place.**
  Breaks v0.4.0 consumers against rule 4, the mistake CR-0002 corrected.
- **Make `equal` an optional refinement of `json_codec`.**
  Keeps third-party codecs compiling, at the cost of two code paths everywhere a document is compared or copied.
  Declined by the owner in favour of requiring it in v3.

## Acceptance

- `ce::X` names the v3 entity, and every v0.4.0 entity is reachable as `ce::v2::X` with its v0.4.0 declaration.
- The v0.4.0 suites pass against `ce::v2` in every preset, alongside the v3 and v1 suites.
- With a matching codec, a decode followed by a typed read, and a typed write followed by an encode, each parse the payload at most once and never serialise it to intermediate text.
  `bench/codec_bench` records the before and after numbers.
- A decode of a document longer than the retention limit stores `json_text`.
- A ThreadSanitizer build copies, compares and reads one event from several threads without a finding.
- The three specification gates stay green at every commit.
